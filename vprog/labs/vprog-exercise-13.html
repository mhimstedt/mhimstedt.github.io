Praktikum 13: Netzwerkprogrammierung

In diesem Praktikum wollen wir verteilte Anwendungen entwickeln, die über Netzwerk miteinander kommunizieren können. Dafür verwenden wir Java unter Nutzung der IDE IntelliJ IDEA.
Konkret: Wir wollen unsere Kontaktliste (AddressBook) nun von einem Server laden. Das Experiment wird auf unserem lokalen PC getestet (Client und Server auf gleichem Rechner). Grundsätzlich kann diese Anwendung aber auch über das Netzwerk genutzt werden. Das setzt allerdings entsprechende Einstellungen der Firewall voraus.

Übergeordnetes Ziel der folgenden Aufgaben ist es, dass Clients sich eine Kontaktliste (Typ AddressBook) von einem Server laden können.

1 - Model-Klassen serialisieren

Bevor wir unser AddressBook über Netzwerk übertragen können, müssen wir zunächst unsere Model-Klassen vorbereiten. Damit wir Java-Objekte aus dem Speicher in Dateien, Netzwerk-Sockets usw. schreiben können, müssen diese in einen Byte-Stream umgewandelt werden. Dieser Prozess nennt sich Serialisierung. In Java gibt es hier analog zu den vielen anderen Bereichen, die wir schon kennengelernt haben (u.a. Datenstrukturen, GUI) wieder Schnittstellen: konkret die Schnittstelle Serializable. Sollen Objekte eigener Klassen serialisiert werden, so müssen Sie diese Schnittstelle implementieren (siehe Beispiel: Networking-Example.zip).
Implementieren Sie für alle Model-Klassen die Serializable-Schnittstelle. Denken Sie daran, die Versionsnummer anzugeben: 
    
            private static final long serialVersionUID = 1L;

Sie können bei allen Klassen zunächst 1L angeben. Sollten Sie Klassen später verändern (vor allem die Attribute), können Sie hier die Versionsnummer anpassen, sodass keine Fehler beim späteren Deserialisieren entstehen.

Für jede Anforderung können Sie bis zu einen Bonuspunkt erwerben.

5 - Multi-Client-Erweiterung (bis zu 2 Bonuspunkte)

Aktuell unterstützt unser Client-Server-Modell nur einen einzigen Client. Sobald der Server eine Verbindung zu einem Client aufgebaut hat, wird dieser beendet. Sollten sich zufällig zwei Clients gleichzeitig mit dem Server verbinden, so wird nur zu einem Client eine Verbindung aufgebaut.

Anforderungen:

  • Der Server behandelt jeden Client in einem eigenen Thread
  • Sollte sich der Client nicht sofort verbinden können (z.B. weil der Server gerade ausgelastet ist oder noch gar nicht gestartet wurde), so soll der Verbindungsaufbau mehrmals wiederholt werden. Die maximale Anzahl Wiederholungsversuche übergeben Sie bitte als Variable (z.B. n=5).
Für jede Anforderung können Sie bis zu einen Bonuspunkt erwerben.
