📝 Pflichtaufgaben (1 Bonuspunkt)

In diesem Praktikum wollen wir den Verkauf von Tickets (z.B. Sport, Konzert) über potentiell mehrere Verkaufsstellen nachstellen. Die Tickets sollen dabei zentral in einem gemeinsamen Ticketbestand (TicketInventory) erfasst werden. Der parallele Verkauf von Tickets an mehreren Stellen soll durch Ticketschalter (TicketCounter) ermöglicht werden. Schauen Sie sich zunächst genau das Klassendiagramm an und setzen Sie beide Klassen um (siehe Aufgabe 1 und 2). Überlegen Sie sich dann, wie der konkurrierende Zugriff auf das Attribut count (Methode sell) durch mehrere Verkaufsstellen synchronisiert werden kann.

Die Ticketschalter sollen solange Tickets verkaufen, bis keine mehr verfügbar sind.



Ihre Lösungen für die Aufgaben 1-3 können Sie in diesem IDE-Fenster bearbeiten:

1 - TicketInventory-Klasse

Lösen Sie bitte die folgenden Teilaufgaben:

  • TicketInventory erstellen: Implementieren Sie bitte die Klasse TicketInventory so wie im Klassendiagramm dargestellt. Dem Konstruktor soll die Anzahl zu verkaufener Tickets (count) übergeben werden.
  • sell-Methode: Die Methode sell soll der Einfachheit halber nur einzelne Tickets verkaufen. Mit dem Aufruf Thread.sleep(100) können Sie die Methode bewusst etwas verzögern, um zu simulieren, dass dort normalerweise Datenbankzugriffe usw. erfolgen.
  • Initialisieren Sie eine TicketInventory mit bspw. 20 Tickets.

2 - TicketCounter-Klasse

Lösen Sie bitte die folgenden Teilaufgaben:

  • TicketCounter erstellen: Implementieren Sie bitte die Klasse TicketCounter so wie im Klassendiagramm dargestellt. Dem Konstruktor soll eine Referenz auf eine (vorher initialiserte) TicketInventory übergeben werden.
  • run-Methode: Die Methode run soll das Verkaufen eines Tickets ermöglichen und dazu die Methode sell der TicketInventory aufrufen. Geben Sie zusätzlich auch den Namen des Schalters sowie das zuletzt verkaufte Ticket (Rückgabewert von sell) mit println aus. Es sollen solange Tickets verkauft werden, bis keine mehr verfügbar sind.
  • Initialisieren Sie mehrere TicketCounter-Instanzen - bspw. 8. Denken Sie daran, immer dieselbe Referenz auf die TicketInventory zu übergeben, da alle Schalter aus demselben Ticketbestand verkaufen sollen.
